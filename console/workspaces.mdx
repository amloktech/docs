An organization holds your team's identity, ownership and billing profile. A workspace groups the borrower records, configuration and activity your team works with. Use separate workspaces when you need distinct datasets or access boundaries.

## Open settings

Open the workspace profile at the top of the left navigation, then choose the relevant settings area. Confirm the selected organization before making changes. Owners manage organization settings, workspace names and team access. **Owners and Developers** can create workspaces in an organization where they already have that role. Sensitive actions may require a recent identity check or MFA.

## Create an organization or workspace

<Steps>
  <Step title="Choose the organization">
    In **Organizations**, select an existing organization. To create a separate organization, select **Create organization**, enter its name and complete the confirmation. You become its Owner; its membership and workspaces are separate from your other organizations.
  </Step>
  <Step title="Create the workspace">
    Open **Workspaces**, select **Create workspace**, and enter its name. The workspace belongs to the currently selected organization. A Developer remains a Developer in the new workspace; creation does not grant Owner access or access to other workspaces.
  </Step>
  <Step title="Select it and prepare Sandbox">
    Select the new workspace and complete its [first-use Sandbox setup](/console/quickstart). New workspaces start with Sandbox access. Live access requires activation by AMLOK.
  </Step>
  <Step title="Invite the right team">
    An Owner opens **Team members** in this workspace and invites the people who need access. New invitations apply only to the selected workspace.
  </Step>
</Steps>

Open a workspace row for its details. Owners can use **Rename**. Changing the display name does not create a new workspace or move records between workspaces.

## Reset Sandbox data

Select the workspace and switch to **Sandbox**, then open **Workspaces > Sandbox data**. An Owner can choose **Start empty** or **Load fresh sample data** as often as needed.

<Warning>
Both actions permanently delete **all Sandbox test data**, including data your team created through the API. The reset affects everyone using this workspace. Coordinate with your team and stop active requests and processing first.
</Warning>

| Option | Result |
| --- | --- |
| **Start empty** | Clears test data and creates a fresh CAD 5,000.00 simulated starting credit allocation. |
| **Load fresh sample data** | Clears test data, restores the starting credits and prepares the six-business sample package. Its simulated activity then affects the balance. |

The confirmation lists what will change. Type the exact workspace name, complete the identity check if requested, and confirm. Sample preparation shows its progress until the run finishes. If processing is still active, wait for it to finish before retrying.

A reset removes borrowers, applications, source data, documents, results, monitoring, events, deliveries, exports, scenario history, API logs and simulated funding and consumption. Old record IDs, download links and pagination cursors no longer work. Previously downloaded files and webhooks already received by your systems cannot be recalled.

It keeps the organization, workspace, team access, API keys, embeddings, webhook settings, negotiated rates and audit history. **Live data and other workspaces are unchanged.** Your existing Sandbox API keys continue to work with the new dataset. The initial setup prompt does not reappear after this explicit choice.

To add another set of samples **without deleting existing tests**, use **Dev Tools > Sandbox scenarios > Load six sample businesses** instead. See [Sandbox scenarios](/console/sandbox).

## Update organization identity

In **Organization settings**, use **Edit name** to update the organization name. Use **Upload logo** to choose a PNG, JPG or WebP image up to 5 MB. The organization logo appears in the workspace profile for workspaces in that organization.

The organization identifier is useful when coordinating setup with your team or support. Keep it distinct from a workspace identifier.

## Review products and changes

In **Products**, inspect the selected workspace environment's Insights and Signal access. Available changes depend on your permissions and activation. Enabling a product does not itself submit an origination or enroll a borrower in monitoring; those are API workflows.

Use **Audit log** to inspect recent organization, workspace and membership changes. Open a record for its action, actor, target and recorded metadata. The view is a recent activity window, not a guarantee of an unlimited historical export.

## Check the scope before changing a setting

| Setting | Scope |
| --- | --- |
| Organization name, logo and billing profile | Organization |
| Organization membership | Organization and its workspaces |
| New workspace invitation | Selected workspace |
| API keys, webhook destinations and product records | Selected workspace environment |
| Balance and autopay configuration | Selected workspace environment |
| Payment method | Organization and environment |
| Personal password, authenticator and sessions | Your account |
