## Follow the evidence trail

1. Open the borrower record in **Origination** or **Portfolio**.
2. Read the result's summary, coverage and timestamps.
3. Open **Documents** or **Integrations**, where available, to inspect the supporting records.
4. Compare the evidence identifiers with those returned in **API response** or the related API records.
5. Use [Data Lookup](/console/data-lookup) to understand an unfamiliar normalized field, its type and its meaning.

## Read each layer correctly

| Layer | Example | How to use it |
| --- | --- | --- |
| Application input | Requested financing amount, business facts or supplied documents | Confirm what your institution submitted. |
| Source evidence | Account activity, accounting data or verification findings | Check the source, subject, observation date and coverage. |
| Normalized or enriched data | Standardized transactions, identities and financial measurements | Read units, time period, calculation and provenance when provided. |
| Underwriting conclusion | A policy result, reason or risk dimension | Review the evidence and limitations behind the conclusion. |

Do not treat an unverified business name match as a completed business verification. For identity and business checks, distinguish the entity from associated people, and a screening match from a confirmed finding. The [verification field reference](/api-reference/verification-fields) defines the normalized structures.

## Work with documents

Your integration submits application documents through the [document workflow](/api-reference/documents). In an Origination or Portfolio drawer, open **Documents**:

- **Associated documents** shows files linked to the case. For Origination, this includes primary and participant document IDs and uploads targeted at its requirements. For Portfolio, it includes the monitored deal, baseline and latest package associations. An associated file is not necessarily evidence used in every published result.
- **Other borrower documents** shows additional primary-borrower files outside those case associations. A file uploaded later is discoverable here without changing historical underwriting.

Open the borrower's profile to inspect its **Related records**, including files uploaded before any underwriting or monitoring exists. Use the stable borrower ID to distinguish identities with the same name.

An upload's `202` response means **Processing**. Read its status until **Available** or **Rejected**. Initial underwriting accepts only available files; inspect the failure and submit a corrected upload when rejected. **Restricted** means current authorization no longer allows access. For an available document, select **Download file**, or use **Download** in the case drawer's Documents tab. The download returns the original file, not its metadata. Access and source consent are checked again for each download.

Document metadata is not the file itself. A file may still be processing, unavailable or outside your current access. The Console obtains fresh download authorization when you select Download. For API downloads, obtain a fresh link when the temporary URL expires; keep the document ID as the permanent reference.

## Add information after a result

A completed risk package preserves the documents and evidence used for that result. Uploading another file for the same borrower does not alter it. To assess the new information, wait for the file to become available, then submit a reassessment that explicitly includes it. Use the same application reference, `supersedes_origination_id` and a new command key as described in [documents](/api-reference/documents).

If an origination is still accepting a document requirement, target that requirement with the correct borrower and origination IDs. Successful inspection accepts the file and resolves the requirement; a `202` upload receipt alone does not.

## Investigate incomplete or conflicting evidence

- **Missing source:** check whether the borrower connected the required integration and granted the necessary consent.
- **Stale source:** compare the last observation or refresh with the result's evaluation time.
- **Missing field:** check whether the field is nullable, not supplied by that source or outside the requested coverage.
- **Conflicting values:** compare source, subject, currency and reporting period before concluding that values disagree.
- **Processing error:** trace the related request or job instead of assuming the evidence is empty.

Use stable record identifiers for reconciliation. Avoid copying credentials or unnecessary borrower documents into support messages. For complete data retrieval beyond what the console displays, follow [data access](/api-reference/data-access) and [large results](/api-reference/large-results).
