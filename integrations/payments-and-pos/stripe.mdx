## Data refresh

**Provider update cadence:** On supported events; API reads for reconciliation.

Stripe emits webhooks when supported payment, refund, dispute, and payout events occur. API reads retrieve the corresponding resources; there is no single recurring refresh interval for all payment data.

Event delivery can be delayed, duplicated, or out of order. Settlement and funds availability follow the payment lifecycle, so an event does not imply funds have settled.

**AMLOK synchronization:** The enabled refresh mode and schedule are agreed for your connection. Provider timing describes upstream capability; allow for retrieval and processing before changes appear in AMLOK. See [data refresh and freshness](/integrations/data-refresh).

Provider references: [Stripe webhooks](https://docs.stripe.com/webhooks), [Stripe event types](https://docs.stripe.com/api/events/types).
