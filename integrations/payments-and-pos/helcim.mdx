## Integration approach

Card transaction API; confirm payout/fee coverage and suitable merchant authorization.

## Access and approval

Merchant creates permissioned token; third-party commercial approval requirements/ETA ND.

**Documentation availability:** Public API/docs.

*ND means the source catalog does not disclose an approval estimate.*

{/* BEGIN PROVIDER REFRESH */}
## Data refresh

**Provider update cadence:** After supported card-transaction events.

Helcim sends a webhook after a supported card transaction is processed. The notification identifies the transaction; the Card Transaction API supplies its full details.

Webhooks must be enabled for the required events. Delivery retries can delay updates. The card-transaction event does not establish a recurring refresh interval for every Helcim resource.

**AMLOK synchronization:** The enabled refresh mode and schedule are agreed for your connection. Provider timing describes upstream capability; allow for retrieval and processing before changes appear in AMLOK. See [data refresh and freshness](/integrations/data-refresh).

Provider references: [Helcim webhooks](https://devdocs.helcim.com/docs/webhooks).
