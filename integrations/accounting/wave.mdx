## Integration approach

GraphQL/API assessment; verify financial-statement and ledger coverage; supplement with exports when needed.

## Access and approval

Wave approval and OAuth required for integrations beyond your own account; ETA ND. Minutes to create an app is not approval. Review source.

**Documentation availability:** Public GraphQL API/docs.

*ND means the source catalog does not disclose an approval estimate.*

{/* BEGIN PROVIDER REFRESH */}
## Data refresh

**Provider update cadence:** On supported invoice, estimate, and checkout events.

Wave supports webhooks for selected invoice, estimate, and checkout events. Receiving webhooks requires an authorized Pro account and the appropriate OAuth scopes.

These notifications do not represent every ledger or bank-feed change. Other accessible resources require API retrieval on the configured schedule. Missing scopes prevent delivery for the affected business.

**AMLOK synchronization:** The enabled refresh mode and schedule are agreed for your connection. Provider timing describes upstream capability; allow for retrieval and processing before changes appear in AMLOK. See [data refresh and freshness](/integrations/data-refresh).

Provider references: [Wave webhook setup and event coverage](https://developer.waveapps.com/hc/en-us/articles/51070420388628-Webhooks-Setup-Guide).
