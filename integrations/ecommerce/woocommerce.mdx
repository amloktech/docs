## Integration approach

Store REST API with read credentials; assess plugin compatibility, pagination and security.

## Access and approval

Store-owner-issued credentials; N/A central vendor review for private connector. Marketplace distribution is separate.

**Documentation availability:** Public API/docs.

## Data refresh

**Provider update cadence:** On supported changes; delivery depends on the store.

WooCommerce supports webhooks for changes to orders, products, customers, and coupons. Notifications are delivered through the store's background processing; API reads can reconcile supported resources.

Store hosting, background jobs, plugins, and webhook health affect delivery time. Webhooks can be disabled after repeated failures. There is no universal minute-based refresh promise across WooCommerce stores.

**AMLOK synchronization:** The enabled refresh mode and schedule are agreed for your connection. Provider timing describes upstream capability; allow for retrieval and processing before changes appear in AMLOK. See [data refresh and freshness](/integrations/data-refresh).

Provider references: [WooCommerce webhooks](https://developer.woocommerce.com/docs/best-practices/urls-and-routing/webhooks), [WooCommerce webhook delivery](https://developer.woocommerce.com/docs/apis/rest-api/v2/webhooks).
