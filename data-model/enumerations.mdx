AMLOK uses different schemas for public product state and source-normalized observations. A normalized `connection` or `monitor` record is evidence; it is not the `Connection` or `Monitor` returned by its product endpoint. Use the schema matching the response path. No endpoint or second API is introduced by these evidence names.

## Product response states

| Response schema and field | Allowed values |
| --- | --- |
| `Connection.status` | `pending`, `connected`, `reauthorization_required`, `revoked`, `failed` |
| `Connection.data_status` | `not_started`, `collecting`, `ready`, `partial`, `failed` |
| `Consent.status` | `active`, `revoked`, `expired` |
| `Origination.status` | `accepted`, `collecting`, `requires_action`, `processing`, `waiting_for_credits`, `completed`, `failed`, `cancelled` |
| `Monitor.status` | `initializing`, `active`, `paused`, `requires_action`, `waiting_for_credits`, `stopped`, `failed` |
| `MonitoringRun.status` | `processing`, `completed`, `partial`, `failed`, `skipped` |
| `Alert.status` | `open`, `resolved` |
| `Export.status` | `queued`, `processing`, `completed`, `failed` |
| `DataRecord.access` | `available`, `restricted`, `deleted` |

## Source-normalized enums

The sections below use exact `NormalizedEnum_*` schemas from OpenAPI. These are field values, not webhook event names. Public notifications use the [event catalog](/api-reference/event-catalog). Values for research labels remain in the research dataset definition.
