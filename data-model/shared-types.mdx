AMLOK uses the following shared types across its single public API. The [OpenAPI contract](/openapi/amlok.json) defines every required field, null rule and validation constraint.

| Type | Meaning |
| --- | --- |
| `Meta` | Request ID, API schema version and Sandbox or Live environment |
| `Money` | Non-negative decimal-string amount with two fractional digits and ISO currency |
| `Window` | UTC observation interval including start and excluding end |
| `Page` | Stable snapshot ID, opaque next cursor and has-more flag |
| `EventPage` | Durable event-feed position for bootstrap and incremental reconciliation |
| `Error` | Code, message, retryable flag, request ID and nullable field path |
| `VersionReference` | Immutable definition ID, revision and SHA-256 hash |
| `Metric` | Decimal-string result or explicit missing reason, units, window, calculation revision and evidence IDs |
| `SourceCoverage` | Per-connection freshness, observation window, coverage state and limitations |
| `EvidenceSummary` | Exact normalized record version, source, hash and access state |
| `Evidence` | Record summary, typed normalized content and optional licensed-report document ID |
| `Event` | Minimal resource notification containing type, timestamp, resource ID/version and environment |
| `DownloadLink` | Authorized short-lived URL, expiry, content hash and MIME type |

## Response envelope

Successful responses contain `data` and `meta`. Collection reads also contain `page`. Errors contain `error`. [Response format](/api-reference/response-format) includes a complete example.

## Financial and missing values

Money uses decimal strings, never floating-point JSON numbers. Billing movements may be signed; `Money` amounts are non-negative. Metric precision follows its definition. Null is different from zero or false; unavailable metrics include a reason and cannot silently pass a risk rule.

## Evidence variants

The `normalized` member of `Evidence` uses a typed resource variant selected by its `object` discriminator. Resource definitions and field meanings are listed in the [field dictionary](/data-model/field-dictionary). Restricted evidence exposes permitted metadata and an access reason without the hidden payload. These resource variants do not introduce separate public collection endpoints.

## Notifications

Use the `Event` schema and [event catalog](/api-reference/event-catalog) for both webhooks and the event feed. Notifications carry resource references; retrieve sensitive evidence through authorized API reads. Verify signatures against the [exact raw body](/api-reference/webhooks).

## Source precision and large results

`Money` is the two-decimal application/deal type. `NormalizedMoney` and source-normalized amount fields retain the precision allowed by their field schema; these are different types. Billing values use the billing rounding policy. `RiskPackageSummary`, typed `RiskPackageSection` variants, `ExportArtifact` and `ExportDownloadLink` support [bounded retrieval](/api-reference/large-results). Detailed KYC/KYB fields use the [verification dictionary](/api-reference/verification-fields).
