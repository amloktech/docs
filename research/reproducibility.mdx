The research package includes executable synthetic training, raw prediction outputs, numerical checks, source references, and a public-data calculation. It uses no API credentials or real borrower records. Its purpose is to make the limited executed evidence inspectable and the larger research protocol actionable.

[Download the reproducibility bundle](https://raw.githubusercontent.com/amloktech/docs/322a7df1208d294318b9cf3e13a307d1ed758936/downloads/research/amlok-research-0.1.zip). The ZIP contains generated arrays, six transformer checkpoints, predictions, measured results, charts, code, the public FX source snapshot, and a per-file integrity manifest. Its SHA-256 is `243ccbc7bec85b18ffe66d3a5099cc32b3b76a30f08fb4d1117e06ffa822994e`.

## What was executed

- A fixed-seed generator produced 1,200 synthetic subjects and 100,800 monthly source observations.
- Three structured-data baselines and six small transformer runs were fitted and evaluated.
- Transformer variants compare training from scratch with masked-value pretraining, across three seeds each.
- Results include held-out predictions, losses, parameter counts, timings, environment versions, and file digests.
- A separate public-data analysis calculated descriptive statistics for Bank of Canada FX observations.
- Contract checks test selected temporal, reconciliation, isolation, and numerical invariants on explicit fixtures.

## Run locally

From the documentation repository, use an isolated Python 3.12 environment:

```bash
python3 -m venv /tmp/amlok-research-env
/tmp/amlok-research-env/bin/python -m pip install -r scripts/research/requirements.txt
/tmp/amlok-research-env/bin/python scripts/research/run_synthetic_study.py
/tmp/amlok-research-env/bin/python scripts/research/public_data.py
/tmp/amlok-research-env/bin/python scripts/research/render_results.py
/tmp/amlok-research-env/bin/python scripts/research/test_research.py
```

The public-data step accesses only the stated Bank of Canada endpoint. Other steps read local files. Allow for environment-dependent floating-point differences; compare metrics with stated tolerances rather than expecting identical elapsed times. The experiment uses CPU execution and two PyTorch threads. No hosted model calls or paid cloud training occur.

## Reproduction boundaries

Reproducing a generated-data result verifies the delivered code and experiment under its assumptions. It does not verify production AMLOK, prove deployment, confirm data rights for a future corpus, or establish predictive performance on real borrowers.

For real-cohort work, keep restricted data and identifiers in the authorized research environment. Share hashes, schemas, aggregate counts, redacted methods, and reviewed result tables. Preserve raw predictions for audit under controlled access. Apply retention, cancellation, and approved training-purpose rules to all derived artifacts, including embeddings and checkpoints.

## Research sequence

First finalize the task and source rights. Then acquire authorized outcome-linked cohorts, freeze the labeling and split protocol, run transparent baselines, test the proposed representation with ablations, calibrate, and obtain independent review. Follow with a prospective shadow study and a controlled assessment of operational impact. This sequence is an evidence plan, not a schedule or a claim that each step has occurred.
