Events are durable notifications of committed resource changes. They contain identifiers and versions, not full financial payloads. Fetch the resource with an authorized server-side key. Event recording, outbound delivery and your business processing are separate outcomes.

## Envelope and permissions

Every notification uses the same [Event schema](/openapi/amlok.json): `id`, `type`, `occurred_at`, `resource_type`, `resource_id`, `resource_version`, nullable `borrower_id` and `environment` (`sandbox` or `live`). A resource without a direct borrower relationship can have `borrower_id: null`; fetch its parent to resolve the borrower.

Use `events:read` to inspect events and deliveries, and `events:write` for replay, plus the read scope in each entry below. Lists omit unauthorized entries; direct reads/replays reject them. Billing requires Owner authority. Resource reads also enforce current consent and product access.

## `embedding_session.completed`

The borrower finishes the Hub connection flow.

Fetch the session and its connection IDs. Completion does not mean underwriting is complete.

Resource: `embedding_session`. Read operation: `getEmbeddingSession`. Additional scope: `connections:read`.

## `connection.action_required`

A connection needs borrower action, such as renewed authorization.

Fetch the connection and start an authorized Hub reauthorization flow; do not retry credentials yourself.

Resource: `connection`. Read operation: `getConnection`. Additional scope: `connections:read`.

## `connection.status_changed`

Connection authorization, availability or collection status changes.

Reconcile status, data_status, freshness and consent before using source data.

Resource: `connection`. Read operation: `getConnection`. Additional scope: `connections:read`.

## `origination.action_required`

An assessment pauses for documents, consent or another explicit requirement.

Read requirements and supply the requested input; a submission receipt is not an approval.

Resource: `origination`. Read operation: `getOrigination`. Additional scope: `insights:read`.

## `origination.status_changed`

Origination processing enters another nonterminal state, including waiting_for_credits.

Read current status and requirements. Follow the specific completion/failure events for terminal outcomes.

Resource: `origination`. Read operation: `getOrigination`. Additional scope: `insights:read`.

## `origination.completed`

Underwriting processing finishes and a risk package is available.

Fetch the origination and risk package. Completed includes approve, decline and review recommendations; it is not a lending approval.

Resource: `origination`. Read operation: `getOrigination`. Additional scope: `insights:read`.

## `origination.failed`

Underwriting ends without a successful result.

Read failure.code and request_id, correct the cause, and use a new command only for an intentional new assessment.

Resource: `origination`. Read operation: `getOrigination`. Additional scope: `insights:read`.

## `risk_package.created`

A new immutable Insights or Signal risk package is committed.

Read the package, completeness, dimensions, evidence and policy results with results:read and the required product entitlement.

Resource: `risk_package`. Read operation: `getRiskPackage`. Additional scope: `results:read`.

## `monitor.status_changed`

Monitoring configuration or lifecycle changes, including active, paused, requires_action, waiting_for_credits, stopped or failed.

Fetch the monitor. Paused or blocked monitoring must not be interpreted as a clean risk evaluation.

Resource: `monitor`. Read operation: `getMonitor`. Additional scope: `signal:read`.

## `monitoring_run.completed`

A monitoring evaluation finishes as completed or partial.

Fetch the run, sources, limitations, deal snapshot and risk package. Partial coverage is explicit.

Resource: `monitoring_run`. Read operation: `getMonitoringRun`. Additional scope: `signal:read`.

## `monitoring_run.failed`

A monitoring evaluation terminates as failed or skipped without a new risk conclusion.

Inspect the run failure and current monitor. Preserve the previous result; do not treat this as an all-clear.

Resource: `monitoring_run`. Read operation: `getMonitoringRun`. Additional scope: `signal:read`.

## `alert.created`

A policy condition becomes an open monitoring alert.

Fetch severity, rule, evidence and package references. Start your own intervention workflow; this API does not manage lender cases.

Resource: `alert`. Read operation: `getAlert`. Additional scope: `signal:read`.

## `alert.updated`

An existing open alert receives a newer evaluation, value or evidence.

Fetch the same alert ID and its current package; this is a continuing condition, not another intervention case.

Resource: `alert`. Read operation: `getAlert`. Additional scope: `signal:read`.

## `alert.resolved`

Comparable evidence satisfies the old policy condition, or the old policy is superseded. Inspect the resolution explanation; policy replacement does not prove risk recovery.

Fetch the resolved alert and package. A delivery retry or manual acknowledgment does not resolve risk.

Resource: `alert`. Read operation: `getAlert`. Additional scope: `signal:read`.

## `export.ready`

An export finishes and can be downloaded.

Fetch the export and request a short-lived download link before expiry. The webhook contains no file or signed URL.

Resource: `export`. Read operation: `getExport`. Additional scope: `exports:read`.

## `export.failed`

Export generation fails.

Read failure and correct format, input or size constraints before requesting a new export.

Resource: `export`. Read operation: `getExport`. Additional scope: `exports:read`.

## `data.updated`

New normalized data is available for a connection.

Resume the normalized-data change feed. resource_version identifies the updated connection, not a count of rows.

Resource: `connection`. Read operation: `getConnection`. Additional scope: `data:read`.

## `document.status_changed`

Document processing or access status changes.

Fetch the document and inspect available, rejected or restricted status and failure before using it.

Resource: `document`. Read operation: `getDocument`. Additional scope: `evidence:read`.

## `billing.payment_updated`

A funding payment changes state, for example pending, succeeded, failed or returned.

Owners with billing:read reconcile the payment; a pending payment is not spendable credit.

Resource: `billing_payment`. Read operation: `getBillingPayment`. Additional scope: `billing:read`.

## `billing.transaction_posted`

An immutable funding, usage, adjustment or refund ledger transaction is posted.

Read the transaction and billing summary. Reconcile by transaction ID, never by webhook arrival order.

Resource: `billing_transaction`. Read operation: `getBillingTransaction`. Additional scope: `billing:read`.

## `deal_snapshot.created`

A new immutable lender-supplied deal snapshot is accepted.

Read its sequence and effective time. This records lender input; it does not rerun historical underwriting.

Resource: `deal_snapshot`. Read operation: `getDealSnapshot`. Additional scope: `signal:read`.

## Delivery semantics

An origination decline is a completed assessment with a decline recommendation, not `origination.failed`. A risk alert is different from a processing failure. There is no webhook for every HTTP 4xx/5xx request: inspect request logs and the [error catalog](/api-reference/errors). Browser `amlok.hub.*` postMessage notifications are a separate channel; see [embedded Hub integration](/api-reference/integration-hub).

Deduplicate by workspace/environment + event ID. Event IDs survive replay; delivery IDs do not. Arrival order is not guaranteed. Reconcile resource versions and use the event feed for gaps. Specific completion/action events can replace a generic status event; do not require both for the same version.

See [signatures and receivers](/api-reference/webhooks), [operations and retries](/api-reference/webhook-operations), and [Console configuration](/console/webhooks).
