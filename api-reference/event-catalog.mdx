AMLOK events notify you of product and connection changes. Each payload contains an event ID, type, occurrence time, resource type/ID/version, nullable borrower ID and environment. This is the same envelope used by signed webhooks and the durable event feed.

```json
{
  "id": "evt_synthetic",
  "type": "origination.completed",
  "occurred_at": "2026-11-06T12:00:00Z",
  "resource_type": "origination",
  "resource_id": "orgn_synthetic",
  "resource_version": 4,
  "borrower_id": "bor_synthetic",
  "environment": "sandbox"
}
```

| Event | Follow-up |
| --- | --- |
| `embedding_session.completed` | Retrieve the referenced resource and compare its version. |
| `connection.action_required` | Retrieve the referenced resource and compare its version. |
| `connection.status_changed` | Retrieve the referenced resource and compare its version. |
| `origination.action_required` | Retrieve the referenced resource and compare its version. |
| `origination.status_changed` | Retrieve the referenced resource and compare its version. |
| `origination.completed` | Retrieve the referenced resource and compare its version. |
| `origination.failed` | Retrieve the referenced resource and compare its version. |
| `risk_package.created` | Retrieve the referenced resource and compare its version. |
| `monitor.status_changed` | Retrieve the referenced resource and compare its version. |
| `monitoring_run.completed` | Retrieve the referenced resource and compare its version. |
| `monitoring_run.failed` | Retrieve the referenced resource and compare its version. |
| `alert.created` | Retrieve the referenced resource and compare its version. |
| `alert.resolved` | Retrieve the referenced resource and compare its version. |
| `export.ready` | Retrieve the referenced resource and compare its version. |
| `export.failed` | Retrieve the referenced resource and compare its version. |

Delivery is at least once and may be out of order. Deduplicate by event ID. Resource versions are meaningful only within the same resource. An immutable package has version 1; mutable status resources increment their version. Fetching a newer resource than the event is expected.

A run failure and a risk alert describe different problems. Missing data must not be treated as a healthy risk result. Events never contain borrower credentials, complete financial payloads or signed download URLs.
