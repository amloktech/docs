AMLOK events notify you of product and connection changes. Each payload contains an event ID, type, occurrence time, resource type/ID/version, nullable borrower ID and environment. This is the same envelope used by signed webhooks and the durable event feed.

```json
{
  "id": "evt_synthetic",
  "type": "origination.completed",
  "occurred_at": "2026-11-06T12:00:00Z",
  "resource_type": "origination",
  "resource_id": "orgn_synthetic",
  "resource_version": 4,
  "borrower_id": "bor_synthetic",
  "environment": "sandbox"
}
```

Delivery is at least once and may be out of order. Deduplicate by event ID. Resource versions are meaningful only within the same resource. An immutable package has version 1; mutable status resources increment their version. Fetching a newer resource than the event is expected.

A run failure and a risk alert describe different problems. Missing data must not be treated as a healthy risk result. Events never contain borrower credentials, complete financial payloads or signed download URLs.

## Data and billing notifications

- data.updated references a connection whose committed data changed. Continue the Data API cursor; the event does not carry records and is not a sync job to execute.
- document.status_changed references the document to inspect for availability or rejection.
- billing.payment_updated references a payment's current state. A successful delivery of this notification does not itself post credits.
- billing.transaction_posted references an immutable wallet entry. Use the billing snapshot APIs for reconciliation.

Only authorized destinations and event readers receive the corresponding resource metadata. Billing notification delivery, reads and replay require Owner authority and billing:read; data notifications require data:read. Losing access stops further delivery and does not permit replay of restricted events.
