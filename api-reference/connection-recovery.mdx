Inspect `GET /v1/connections` for source status, consent, last successful sync, source-as-of time and coverage. Connection health and data freshness are different: a connected account can still have stale or incomplete evidence.

When a source requires authorization again, create an embedding session with `purpose: reauthorize` and the `connection_id`. Use the same borrower and a compatible published embedding version. Send the new short-lived launch URL to that borrower and verify completion server-side.

```json
{
  "borrower_id": "bor_synthetic",
  "embedding_version_id": "embed_synthetic",
  "purpose": "reauthorize",
  "return_url": "https://institution.example.com/connected",
  "consent_purposes": [
    "credit_assessment",
    "continuous_monitoring"
  ],
  "embed_origin": "https://institution.example.com",
  "connection_id": "con_synthetic"
}
```

Complete Origination requirements through the indicated connection or document action. AMLOK resumes collection and assessment when dependencies permit. Do not start a provider sync or retry an internal workflow.

Revoke authorization with `POST /v1/consents/{id}/revoke` when appropriate. Revocation stops future collection under that consent and does not rewrite previous assessments or bypass retention policy.

{/* BEGIN BORROWER LIFECYCLE */}
## Restart collection and monitoring

If the source is failed or needs renewed authorization, complete a fresh borrower-bound reauthorization session and confirm the source's returned state. That completion schedules source collection again. An archived borrower must be restored first; cancelled old Hub sessions are not reused.

For a failed, paused, blocked or stopped Monitor, resolve the source issue and then explicitly PATCH the Monitor to `active` using its current ETag. Updating the connection alone must not be interpreted as a completed monitoring evaluation.
{/* END BORROWER LIFECYCLE */}
## What consent revocation changes

Send `POST /v1/consents/{id}/revoke` with a `reason`. The returned Consent records that value in `revocation_reason`, together with `revoked_at`. Repeating revocation preserves the original reason and timestamp; it does not replace the audit record. Older records can omit `revocation_reason`.

Revocation marks the affected connections `revoked` and immediately moves unfinished originations and running monitors that depend on them to `requires_action`. Inspect `requirements` for the source and required consent purpose. This includes sources belonging to related parties. Paused, stopped and failed monitors keep their current state. Source collection and publication cannot continue under the withdrawn consent.

Historical assessments, evidence references, runs and charges remain recorded. Retention does not grant access: source data and documents can become `restricted`, and a risk package containing unauthorized sources cannot be retrieved. Revocation is not a data-deletion request. See [data access](/api-reference/data-access).

Obtain a new affirmative borrower authorization through a reauthorization Hub session. Review the resulting connection and workflow state. Explicitly paused or stopped monitors need an explicit resume; consent renewal does not turn them on.
