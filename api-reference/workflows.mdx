## Verify an applicant

Create a business/person, obtain authorization, and upload permitted evidence. [Start verification](/api-reference/endpoints/identity/start-verification) with an approved workflow version. If a hosted URL is returned, route the applicant through it and wait for the result.

Retrieve checks and screening matches. `in_review`, unresolved identity, missing ownership evidence, and possible screening matches require explicit handling. Completion is not the same as a verified identity or institutional approval.

## Underwrite from frozen evidence

1. [Create the application](/api-reference/endpoints/lending/create-application) with exact amount and currency.
2. Connect and synchronize authorized sources, then inspect coverage and freshness.
3. [List ready input manifests](/api-reference/endpoints/risk/list-input-manifests) for the subject after synchronization. Use the returned manifest ID for [attribute calculations](/api-reference/endpoints/risk/calculate-attributes), with a calculation window contained in the frozen manifest window. Retrieve the manifest to confirm coverage; missing coverage is not a zero value.
4. [Start an underwriting run](/api-reference/endpoints/operations/start-workflow-run) with `workflow_type: underwrite`, an approved version, and input resource IDs.
5. Retrieve the decision and immutable risk snapshot. Distinguish an advisory recommendation from the institution's decision.

Missing inputs produce explicit unavailability. Do not replace an unavailable DSCR, credit score, PD, or income verification with an inferred value. Provider bank deposits alone do not establish gross income or employment.

## Observe funding

The API exposes lender-supplied loans, facilities, guarantees, collateral, and repayment schedules. [Credit reporting](/api-reference/credit-reporting) shows prepaid AMLOK service credits and consumption. It provides no payment controls. Borrower funding and filings remain in the institution's authorized systems.

## Monitor an existing exposure

1. [List ready monitoring baselines](/api-reference/endpoints/risk/list-monitoring-baselines) for the borrower/business. AMLOK prepares these from a completed assessment or the agreed existing-portfolio onboarding process. If none is ready, complete that process before creating a monitor.
2. [Retrieve the baseline](/api-reference/endpoints/risk/retrieve-monitoring-baseline) and its linked risk snapshot. The response provides the frozen input-manifest ID and approved snapshot ID.
3. [Create a monitor](/api-reference/endpoints/risk/create-monitor) using the returned `snapshot_id` as `baseline_snapshot_id`, with resource types, attribute keys, cadence, and ruleset version. All linked IDs must belong to the same subject and key-bound workspace.
4. Consume alerts and retrieve supporting evidence. Baseline reads do not launch or charge an Insights underwriting.

Compare comparable time windows and coverage. A data outage is not an improvement in borrower risk. Refresh cadence depends on source capability and consent; a daily requested cadence is not a source freshness guarantee.

For a material change, Signal reassesses risk using existing baseline data and newly processed records. This work is included in Signal and does not launch or charge another Insights underwriting. Preserve the original snapshot and the new evidence for audit. A separately requested full underwriting is a distinct Insights operation.

## Service and investigate

Create a [case](/api-reference/endpoints/operations/create-case) and [task](/api-reference/endpoints/operations/create-task) to gather evidence or record a disposition. The task approval route records authorization against an exact version. Creation of a [communication draft](/api-reference/endpoints/operations/create-communication-draft) does not send it.

The [send route](/api-reference/endpoints/operations/send-approved-communication) requires `communications:send`, a valid approval ID, and `expected_record_version`. Approval ID provisioning must be defined in the deployed workflow; a task ID must not be substituted for an approval ID without an explicit contract.

Use `workflow_type: investigate` for an approved investigation run. Candidate matches remain candidate until reviewed. Record reviewer attribution and supporting evidence; do not use an automated signal as an unsupported accusation.

## Five orchestrated workflow types

`verify`, `underwrite`, `monitor`, `service`, and `investigate` are the workflow enum values. Funding and re-underwriting are lifecycle journeys, not additional enum values.
